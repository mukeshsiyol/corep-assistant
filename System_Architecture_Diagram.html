🏦 LLM-Assisted PRA COREP Reporting System

Modular Architecture for Regulatory Compliance

1 User Interface Layer
Function: Accepts natural language questions and structured scenario inputs from regulatory analysts
Inputs: "Where do I report retained earnings?" + Business data (e.g., capital amounts, deductions)
Outputs: Human-readable COREP template extracts, validation warnings, audit trails
Technology: React/Vue web interface, REST API, JSON schema validation
↓
2 Regulatory Text Retrieval (RAG)
Function: Semantic search over regulatory documents to retrieve relevant guidance
Sources: PRA Rulebook, EBA COREP Instructions, CRR Articles, Supervisory Statements
Process: Query vectorization → Similarity search → Top-k relevant passages (k=5-10)
Technology: Sentence Transformers (all-MiniLM-L6-v2), FAISS/ChromaDB vector database, Document chunking (300-500 tokens)
↓
3 LLM Structured Reasoning Engine
Function: Generates COREP field mappings constrained to predefined JSON schema
Process: Retrieved regulatory text + User scenario → LLM reasoning → Schema-validated output
Safety: Schema constraints prevent hallucination; confidence scores flag uncertain outputs
Technology: Claude Sonnet 4 (or equivalent LLM), Prompt engineering with regulatory context, JSON schema enforcement
↓
4 Validation & Compliance Layer
Function: Applies COREP validation rules and consistency checks
Checks: Mandatory fields, arithmetic consistency (totals = components), value ranges, cross-template consistency
Output: Errors (blocking) and Warnings (review recommended)
Technology: Business rules engine, XBRL validation rules, Custom Python validators
↓
5 Audit Trail & Explainability Layer
Function: Records regulatory justification for each populated field
Content: Source documents, article references, LLM reasoning chain, timestamps
Purpose: Regulatory examination support, internal audit, model risk governance
Technology: Structured logging (JSON), Version-controlled regulatory source tracking, Audit report generation (PDF/Excel)
↓
6 Output Generation Layer
Function: Transforms structured JSON into human-readable COREP template extracts
Formats: Interactive web view, Excel template (analyst review), PDF audit report
Integration: Export to regulatory submission tools (manual process for now)
Technology: Template rendering engines, Excel generation (openpyxl/xlsxwriter), PDF generation (ReportLab)
📊 Data Flow Example: Retained Earnings Query
User Query → RAG Retrieval (PRA Art. 26) → LLM Mapping (Row 050) → Validation (✓ Positive value) → Audit Log → Template Extract
🔒 Security & Compliance
On-premises deployment, no external API calls, role-based access, 7-year audit retention
✅ Human Oversight
All outputs require analyst approval, dual control for material fields, escalation for uncertain cases
📈 Scalability
Modular design enables expansion from 2 to 50+ COREP templates, future integration with banking systems
🔍 Explainability
Every field traceable to regulatory source, confidence scoring, clear audit trail for examinations
